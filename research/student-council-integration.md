## 一、现有工作流分析

### 1.1 当前WPS问卷收集的信息

| 字段 | 类型 | 说明 |
|------|------|------|
| 班级 | 单行文本/下拉 | 学生所在班级编号 |
| 姓名 | 单行文本 | 学生姓名 |

### 1.2 完整招新流程

```
报名阶段 → 面试排期 → 面试通知 → 面试执行 → 结果通知
   WPS问卷      线下/邮件     邮件       线下       邮件
```

当前痛点分析：
- **报名阶段**：WPS问卷功能完善，但与后续流程割裂
- **面试排期**：需人工从WPS导出数据，手动安排
- **通知环节**：完全依赖手动邮件，效率低
- **结果跟踪**：无系统化记录，全靠人工

## 二、WPS表单/多维表格能力评估

### 2.1 WPS多维表格（DBSheet）API能力

WPS开放平台提供了完整的多维表格API体系：

**可用API接口：**
- `GET /v7/dbsheet/{file_id}/sheets/{sheet_id}/forms/{view_id}/fields` — 列出表单字段
- `POST /v7/dbsheet/{file_id}/sheets/{sheet_id}/forms/{view_id}/fields/{field_id}/update` — 更新字段
- `POST /v7/dbsheet/{file_id}/sheets/{sheet_id}/forms/{view_id}/meta` — 更新表单元数据
- 记录的增删查改API（通过DBSheet通用接口）

**权限要求：**
- `kso.dbsheet.read` — 只读权限
- `kso.dbsheet.readwrite` — 读写权限
- 支持应用授权与用户授权
- 限频：10次/秒（按app_id）

**签名方式：** KSO-1签名

### 2.2 WPS AirScript 自动化能力

WPS多维表格内置AirScript脚本引擎，可实现：
- **定时任务**：定期执行脚本（如每天检查新报名）
- **数据校验**：自动检查输入格式正确性
- **自动化流程**：当表单有新提交时触发脚本
- **跨表同步**：自动同步数据到其他表格
- **邮件发送**：通过脚本触发邮件通知（需配置）

**关键限制：**
- AirScript运行在WPS云端，无法直接访问外部网站
- 邮件发送需要通过WPS的内置能力，无法调用外部SMTP
- 脚本执行有时间限制，不适合大批量处理

### 2.3 WPS问卷原生功能

| 功能 | 支持情况 | 说明 |
|------|----------|------|
| 表单设计 | ✅ 支持 | 拖拽式设计，支持多种题型 |
| 数据收集 | ✅ 支持 | 自动汇总到多维表格 |
| 数据导出 | ✅ 支持 | 可导出Excel/CSV |
| 自动回复 | ⚠️ 有限 | 可设置提交后提示语，但无邮件自动回复 |
| 条件逻辑 | ⚠️ 有限 | 基础的显示/隐藏逻辑 |
| Webhook | ❌ 不支持 | 原生无Webhook能力 |
| API读取 | ✅ 支持 | 通过开放平台API读取数据 |
| 实时同步 | ❌ 不支持 | 无法实时推送到外部系统 |

## 三、网站集成可能性分析

### 3.1 现有网站技术架构

```
academic.kcisec.site
├── Jekyll静态站点（GitHub Pages托管）
├── 数据驱动：_data/*.yml 配置文件
├── 布局系统：_layouts/*.html
├── 样式系统：assets/css/main.css（统一设计系统）
├── 交互逻辑：assets/js/*.js（纯前端）
└── 已有功能：
    ├── 狼人杀中控台（纯前端JS应用）
    ├── KC Gaming Chess（数据驱动的赛事页面）
    ├── APP下载中心
    └── 校园资源导航
```

**技术特点：**
- 纯静态站点，无后端服务器
- 数据通过YAML文件注入页面
- 支持自定义JS交互（如狼人杀中控台）
- 统一的深色/浅色主题系统
- 响应式设计，移动端友好

### 3.2 Jekyll站点表单集成方案

由于GitHub Pages是纯静态托管，无法处理POST请求，需要借助第三方服务：

**方案A：Formspree（推荐）**
- 免费层：每月50次提交
- 无需后端代码，纯HTML表单
- 提交后自动发送邮件通知
- 支持重定向到自定义页面
- 反垃圾邮件保护

**方案B：Static Forms**
- 免费层：每月100次提交
- 类似Formspree的功能
- 支持附件上传

**方案C：Google Forms嵌入**
- 完全免费，无提交限制
- 可嵌入iframe
- 数据自动汇总到Google Sheets
- 但需要Google账号，可能有网络访问问题

### 3.3 可在网站实现的功能

| 功能 | 可行性 | 实现方式 |
|------|--------|----------|
| 招新信息展示 | ✅ 完全可行 | 静态页面，类似chess页面结构 |
| 在线报名表单 | ✅ 可行 | 第三方表单服务 + Jekyll |
| 报名状态查询 | ⚠️ 有限 | 需定期手动更新YAML数据 |
| 面试时间选择 | ⚠️ 有限 | 可嵌入外部日历选择工具 |
| 结果公示 | ✅ 完全可行 | 数据驱动的静态页面 |
| 流程时间线 | ✅ 完全可行 | 静态展示招新流程 |

### 4.2 详细分工说明

#### 网站承担的部分（academic.kcisec.site）

**1. 招新信息展示页** `/student-council`
- 学生会介绍
- 各组别职责说明（学术组/活动组/宣传组）
- 招新流程时间线
- 常见问题FAQ
- 联系方式

**2. 报名入口**
- 方案A（推荐）：直接跳转到WPS问卷链接
- 方案B：网站内嵌表单，数据通过API同步到WPS

**3. 结果公示页** `/student-council/results`
- 数据来源：`_data/student-council.yml`
- 展示录取名单（按组别分类）
- 展示面试安排（如有需要）
- 更新方式：手动更新YAML文件后重新构建

#### WPS多维表格承担的部分

**1. 报名数据收集**
- 维持现有WPS问卷不变
- 数据自动汇总到多维表格
- 支持多视图查看（按班级/按组别/按时间）

**2. 数据管理与处理**
- AirScript自动校验数据格式
- 自动标记重复报名
- 生成统计报表（各组别人数、班级分布等）

**3. 邮件通知自动化（通过AirScript）**
```javascript
// AirScript示例：新报名自动通知
async function onFormSubmit(record) {
  // 获取学生信息
  const name = record['姓名'];
  const className = record['班级'];
  const group = record['意向组别'];

  // 发送确认邮件（需WPS邮件能力支持）
  // 注意：实际实现需根据WPS API文档调整
  console.log(`新报名：${className} ${name} - ${group}`);
}
```

#### 邮件承担的部分

**1. 面试通知**
- 发送对象：通过初筛的学生
- 内容：面试时间、地点、注意事项
- 触发方式：WPS AirScript自动发送 或 手动群发

**2. 结果通知**
- 发送对象：所有报名学生
- 内容：录取结果、后续安排
- 触发方式：手动群发（更可控）

**3. 确认回复**
- 发送对象：被录取学生
- 内容：确认是否接受录取
- 要求：需在指定时间前回复

#### AirScript自动化脚本

```javascript
// 每日检查脚本（定时任务触发）
async function dailyCheck() {
  const app = Application;
  const sheet = app.ActiveSheet;

  // 获取所有"待审核"状态的记录
  const records = await sheet Records.query({
    filter: { '状态': '待审核' }
  });

  // 统计各组别人数
  const stats = {
    '学术组': 0,
    '活动组': 0,
    '宣传组': 0
  };

  records.forEach(r => {
    const group = r['意向组别'];
    if (stats[group] !== undefined) {
      stats[group]++;
    }
  });

  console.log('当前报名统计：', JSON.stringify(stats));

  // 如果某组别报名人数超过限额，可触发提醒
  const LIMIT = 20;
  for (const [group, count] of Object.entries(stats)) {
    if (count >= LIMIT) {
      console.warn(`${group}报名人数已达${count}人，接近/超过限额`);
    }
  }
}
```

## 七、风险与备选方案

### 7.1 潜在风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| WPS API调用限制 | 高峰期可能超限 | 提前申请提升配额，错峰处理 |
| AirScript邮件能力有限 | 可能无法自动发送邮件 | 改为手动群发，或使用第三方邮件服务 |
| GitHub Pages构建延迟 | 结果公示更新不及时 | 提前准备好数据，及时推送更新 |
| 学生网络访问问题 | 无法访问WPS或网站 | 提供多种报名渠道（纸质+线上） |

### 7.2 备选方案

**如果WPS AirScript邮件能力不足：**
- 使用WPS的"分享"功能手动发送
- 通过学校邮件系统（@kcisg.com）群发
- 使用QQ群/微信群公告通知

**如果需要更复杂的表单逻辑：**
- 考虑使用Google Forms替代WPS问卷
- 使用Typeform等专业表单工具
- 在网站端使用Formspree等第三方服务

**如果需要实时数据同步：**
- 部署简单的云函数（如Vercel Functions）
- 使用Zapier/Make等自动化平台连接WPS和邮件
- 使用GitHub Actions定时拉取WPS数据并更新网站

## 八、总结

### 核心建议

1. **保持WPS问卷作为数据收集入口** — 功能成熟，学生熟悉，无需额外开发
2. **网站作为信息展示和结果公示平台** — 充分利用现有Jekyll站点能力
3. **邮件作为主要通知渠道** — 正式、可靠、学生习惯
4. **WPS AirScript处理自动化** — 减少人工操作，提高效率

### 分工原则

- **数据收集 → WPS**：专业表单工具，数据管理方便
- **信息展示 → 网站**：视觉效果好，易于分享传播
- **通知触达 → 邮件**：正式可靠，有记录可查
- **流程管理 → WPS + 人工**：灵活可控，适应变化

### 预期效果

- 学生体验：清晰了解招新信息，便捷完成报名
- 管理效率：减少手动数据处理，自动化部分通知
- 信息透明：结果公示及时，流程可追溯
- 可扩展性：后续可增加更多功能（如在线投票、活动报名等）
